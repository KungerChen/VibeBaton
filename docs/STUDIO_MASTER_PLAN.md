## 1. 结论与已拍板的决策

一句话：取消 `Guided | Pro` 顶层分叉，改为一个按「蓝图 → 施工 → 验收」推进的项目工作台；原专业三栏如实降格为右上角的演练场 Lab。开跑只切换阶段，不切换界面。

### 1.1 五条结论

1. **一个工作台，三幕推进。** 删除 `studioMode` 顶层分叉。阶段轨只编号「① 蓝图 ② 施工 ③ 验收」。`setup` 留在后端枚举里，前台降级为顶栏的就绪胶囊。
2. **原专业三栏迁入演练场 Lab。** Lab 只装配方编辑、模拟剧本和案例回放，常驻提示「模拟，不会改动你的项目」。它与真实运行之间只有一座单向桥。
3. **术语透视镜只设开、关两档。** 「开」默认只标用户还没点过「懂了」的词。静态文案显式绑定，动态文本受控匹配，全页共用一个视口浮层。
4. **精简靠分层和语义，不靠删功能。** 四层空间、五级字号、状态色独占、七组重复表面合并，核心功能零牺牲。
5. **创新只投影后端已有的机械事实。** 证据矩阵、交接棒连线卡、谱系时间机器、决策收件箱入选。费用天气预报和常驻副驾砍掉。

对用户原设想最重要的一处修正：三方一致反对字面意义上的「开跑后切入现有专业界面」。方向（单一入口、开跑后信息加深）被采纳，实现方式改为同一外壳内的阶段切换。

| # | 共识 | 依据 |
| --- | --- | --- |
| 1 | 现有 Pro 界面是「离线配方与模拟编辑器 + 堆叠遥测栏」，不驱动真实运行，也没有验收、谱系和回滚闭环 | `_start_run` 只消费 RFC、`mode`、阵容与覆盖值；`engine.py` 不导入 `graph_engine`；`finalizeRun`、`rollbackRun`、`requestChanges`、`getLineageRun` 只在 Guided 侧被调用 |

## 3. 步骤 0：M3 验收方案

M3 的代码已在 `main`（`422f33b` 及之后的修复）。按 LOG 记录，真实浏览器交互、真实模型和 daemon 端到端从未验证过，所以 D、E、F 三组是重点。下面的按钮文案取自 `web/src/i18n/messages.ts`，以界面实际显示为准。

### 3.1 准备

- **用演示仓库，不要用 VibeBaton 自己。** 验收会创建运行、合并到 `main`、做回退。
- **RFC 写小一点。** F 组要连续跑三轮真实运行，会消耗模型额度；例如「在 README 加一行说明」。
- 在仓库根目录用 PowerShell 依次执行：

```powershell
New-Item -ItemType Directory -Force "$env:TEMP\m3-demo"
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
python -m vibebaton ui
```

- Studio 默认进入专业模式，先在顶栏切到「引导模式」，第 1 步里选上面的演示目录。

### 3.2 A 组：自动门禁（RFC 验收标准 5、6）

```powershell
python -m unittest discover -s tests
npm --prefix web test
npm --prefix web run build
```

- 预期全部通过。上次记录是 Python 962 项通过、2 项跳过（约 8 分钟），前端 874 项。
- 已知偶发：`tests/test_allocation.py` 有一项把耗时断言为 `0.0s`，偶尔得到 `0.1s`，单独重跑通过。
- 构建若报 EPERM，改在 `web/` 下运行 `npm run build -- --configLoader runner`。

### 3.3 B 组：第 1 步，工作区与工具

1. 选演示目录并初始化 Git。预期：自动补上首个提交，可以继续。
2. 页面上没有六角色阵容表。
3. 至少一个 CLI 就绪时，CLI 卡片折叠成一行状态摘要。
4. 对未安装的 CLI 点安装。预期：出现内联的命令确认气泡，不是复选框；取消即可，不必真装。
5. 对已安装未登录的 CLI：「登录」按钮高亮；登录后切回窗口会自动重新扫描。本机若都已登录，记为「未覆盖」。

### 3.4 C 组：第 2 步，蓝图与推荐

1. 顶栏 L0 模型切换器自动选中最强的就绪模型，每轮回复显示实际应答的模型名。
2. 一句话起步，一次只问一个问题，清单逐项点亮。
3. 中途切换 L0 模型再答一轮。预期：蓝图草稿不丢、不漂移。
4. 有在线草稿后断网再发一轮。预期：旧草稿保留并出现重试，不被离线模板覆盖。
5. 就绪后对话区下方出现推荐卡片：一句结论、最多三条理由、团队表、「专家小组」开关、「调整团队」、「开始施工」。卡片里不应出现 `claude_sub` 这类内部 ID。
6. 标准 3：汇总模型或某位专家未就绪时，不推荐专家小组，开关处给出原因并列出缺谁；强行启动应被拦住并引导回自动施工。本机若全部就绪，记为「未覆盖」。
7. 在「调整团队」里改一个角色，再走一轮推荐。预期：保留用户定的团队。

### 3.5 D 组：发车与恢复（标准 4）

1. 快速双击「开始施工」。预期：只产生一个运行。
2. 施工中按 F5。预期：回到同一运行的画布。
3. 关掉浏览器再打开。预期同上。
4. 在蓝图阶段刷新。预期：草稿、清单、工作流选择都还在。

### 3.6 E 组：第 3 步，施工

1. 出现人工决策时是右侧抽屉，不是遮罩弹窗；抽屉开着时仍能点任务节点、看日志和改动。
2. 抽屉开着时刷新。预期：抽屉恢复。
3. 运行失败时出现指引横幅和「停止并重新规划」。预期：点击后运行干净终止，回到蓝图并带上失败原因。
   - 制造失败的一种办法是在 RFC 的检查命令里写一条必然失败的命令。它最终是进入失败还是先升级到人工决策，取决于重试策略，未实测。

### 3.7 F 组：第 4 步，验收与谱系（标准 1、2）

1. 第一轮跑完得到 A。在验收页点「要求修改」。预期：回到蓝图，五项清单已预先点亮，一轮即可再发车，得到 B。再做一次得到 C。
2. 演示仓库的 `.baton/runs/` 下每轮各有一份 `00_RFC.md`，互不覆盖。
3. 父运行应为已被替代状态。在旧标签页里对 A 或 B 点恢复或批准，预期被拒绝。
4. 在 C 上「退回」上一轮。预期：结果回到 B 的内容。
5. 再「放弃」全部未合并改动。预期：回到 A。预期这两步能在同一条链上先后做，但未核实；界面不允许就另起一条链。
6. 标准 2：批准前，先在演示仓库的 `main` 上手动提交一次，再点「批准并合并」。预期：检测到 `main` 已前进，在隔离工作树里重新整合并重跑检查；合并后 `git log main` 里手动提交还在。
7. 合并后立刻「撤销合并」。预期：`main` 回到合并前。若合并后 `main` 又有新提交，预期不做重置，而是引导用 `git revert`。

已知缺陷：演示仓库没有配置检查命令时，第 6 步重整合后标题会显示「检查已通过」，明细却写着没有检查（见 5.5 的假绿灯）。它算不算 M3 的阻塞项由用户定；本方案把修复排在 Phase 1。

- **为什么要立新 RFC**：现行 `.baton/00_RFC.md` 是 Guided Mode 2.0，它把「重做专业模式画布」列为非目标，与本方案冲突。

## 5. 目标架构：三幕渐进工作台 + 演练场 Lab

### 5.1 流转

后端四态 `setup | blueprint | build | signoff` 原样保留，前台只给后三态编号。

```text
┌─ 项目工作台 Build（一个外壳，阶段轨只编号 ①②③）──────────────────────────┐
│                                                                          │
│ [就绪检查] ──已就绪──> [① 蓝图] ──幂等发车──> [② 施工] ──运行结束──> [③ 验收] │
│  Git+可用阵容          blueprint              build                signoff │
│   │   ▲                 ▲   ▲                                        │    │
│ 未就绪 修复后返回         │   └──── 返工：带修改意见建立子修订 ───────────┘    │
│   ▼   │                 │                                                 │
│ [环境向导]               │                                                 │
│ 由就绪胶囊展开，不占编号   │                                                 │
└─────────────────────────┼─────────────────────────────────────────────────┘
                          │ 唯一的桥：带这套阵容去发车
                   [演练场 Lab]
                   顶栏右上角的次级入口；只装模拟数据；离线可用；
                   不改写 Build 的订阅与选中运行
```

- 就绪检查是持续派生的状态，只在未就绪时展开环境向导。
- 发车后外壳不变，主舞台从蓝图换成接力图。
- 验收不满意时带着修改意见回到蓝图并建立子修订。
- 真实运行的回放在施工底坞的时间轴，不在 Lab。

### 5.2 布局线框

```text
顶栏    工作区 ▾ | 就绪胶囊 | ………… | 收件箱(n) | 术语镜 | 演练场 ↗ | 设置
阶段轨  ① 蓝图 ── ② 施工 ── ③ 验收              （右端：谱系 A › B › C）

          蓝图：对话 + RFC 原文编辑 / 就绪检查   |    上：通俗摘要 + 主操作
          施工：实时接力图（只读，跟随当前棒）   |    下：技术详情（默认折叠，记忆）
          验收：验收条件 × 证据矩阵            |
底坞    仅施工 / 验收。收起 = 32px 单行最新事件；展开 = 时间轴 | 终端 | 门禁
```

| 区域 | 默认态 | 硬规则 |
| --- | --- | --- |
| 顶栏 | 高 48–56 px，常驻 | 不放 `Build｜Lab` 并列分段；Lab 是右侧次级入口 |
| 阶段轨 | 三步，右端显示谱系 | `setup` 不占编号 |
| 情境抽屉 | 宽 360 px，打开，跟随当前持棒节点，技术详情折叠 | 同一时刻只有一个主人，优先级：待决策、选中对象、运行总览 |
| 底坞 | 收起为 32 px 单行 | 蓝图阶段不出现 |
| 展开记忆 | 按面板类型存 `localStorage` | 只记用户亲手做的展开与收起；不按节点或运行存；不做推断 |
| 阻塞事件 | 收件箱角标加一 | 不抢焦点，不自动弹面板 |

### 5.3 Setup：降级为顶栏就绪胶囊

同一工作区第二次新建任务，第一屏就应当能写 RFC。固定「第 1 步扫描」既繁琐也不安全：就绪状态会在扫描与发车之间过期，比如 CLI 掉登录或工作区变脏。

| 胶囊 | 含义 | 对发车的影响 |
| --- | --- | --- |
| 绿 · 已就绪 | Git 就绪，全部阵容可用 | 不拦 |
| 黄 · 部分可用 | 至少一套阵容可用，另有阵容不可用 | 不拦；发车前核对本次实际所选阵容 |
| 红 · 有阻塞 | Git 未就绪，或没有任何可用阵容 | 发车按钮禁用并写明原因，点原因直达修复 |

胶囊同时带文字和图形，不单靠颜色区分。其余规则：

1. **初始阶段由就绪度决定。** 新会话就绪时，后端走既有阶段转换进入 `blueprint`，前端只呈现服务端确认过的状态。枚举和持久化格式不变。
2. **恢复会话回原处。** 停在 `setup` 的存量会话若已就绪则自动前进；`build` 回原运行，`signoff` 回原验收。
3. **就绪与阶段正交。** 中途变红不回退 `active_stage`，只在用到的地方拦截，并保留正在查看的运行和证据。
4. **向导由「未就绪」触发，不由「首次使用」触发。** 缺什么展开什么。
5. **重检时机有四个：** 切换工作区、修改阵容、主动刷新、发车前。
6. **两个判断不混用。** 胶囊表示「有可用阵容」；发车前的硬检查核对的是「本次实际所选阵容与覆盖值」。
7. **有运行在跑时切换工作区需确认。**

### 5.4 蓝图：双轨入口，同一次发车

引导是默认路径，不是唯一路径。两个入口提交同一份 RFC，共用就绪检查和发车条。

| 入口 | 适合谁 | 行为 |
| --- | --- | --- |
| 引导起草 | 从一句话开始的人 | 沿用现有一问一答和五项蓝图清单 |
| 粘贴 RFC 快车道 | 手里已有 RFC 的人 | 粘贴、拖入或直接编辑原文；复用 `RfcStep` 的就绪评分；两次点击内发车，不补演对话 |

- **幂等发车。** 先保存本次启动参数和 `launch_request_id`，再发请求。超时后重试复用同一个 ID，找回原运行，重复提交只产生一次运行。
- **确认页列出实际生效的内容：** RFC、角色映射、模型、执行方式。发车条上的覆盖项统一标注「仅本次运行」。
- **沿用上次阵容可一键发车。** 返工仍走父子修订协议。
- **模型覆盖改用结构化角色表单。** 旧弹窗的手写 JSON 输入框删除。Fable 主张直接删，Astra 主张保留为带校验的高级导入；本方案取折中：若 Phase 1 核对发现表单覆盖不到的字段，再保留高级导入。

### 5.5 施工与验收

**施工阶段的接力图只读。** 点节点或连线只切换抽屉内容，永不退出实时视图。这从结构上消灭了现在「点预设或加节点就触发 `setLiveViewActive(false)`」的误伤（`App.tsx:787`、`:814`）。

- 抽屉上层回答两个问题：发生了什么，现在能做什么。下层按需展开输入输出、门禁和 Git 引用。
- 底坞展开后有三个标签：时间轴、终端、门禁。
- 只有用户明确选择「跟随最新运行」，新事件才改变当前查看的运行。查看历史时顶栏显示运行短 ID 和「返回当前运行」。
- 按钮写明作用对象，例如「答复任务 T3」「批准并合并到 main」。
- 现施工步骤没有耗时、花费、进度数字，也没有主动暂停。放行标准是 `LiveRunPanel` 的每个字段都能在抽屉或底坞里找到。

**验收先修掉假绿灯。** 漂移重整合返回 `gates: []` 时，标题用 `every(item => item.passed)` 判断，空数组得到真，于是显示「检查已通过」，明细却写着没有配置检查（`GuidedSignOffPanel.tsx:675`）。

- 「合并结果」和「验证结果」分开展示。
- 验证结果四态：通过、失败、未配置、未返回。空数组显示「无门禁记录」，不用绿色。
- 默认加载器把 `currentBaseSha` 设为 `null`（`GuidedSignOffPanel.tsx:155`），所以批准前显示「提交时由服务端核对 HEAD」。提前显示漂移需要新增实时基准查询，本方案未立项。
- 谱系时间机器上线前，三个回滚按钮先各自写明：未合并时退回上轮结果 `C → B`；放弃整条修订回到 `A`；合并后仅当合并提交仍是分支 HEAD 时恢复到合并前。

### 5.6 Lab：隔离边界

Lab 承接原专业三栏的全部功能。大佬的「跑前拓扑编排」没有丢失风险，因为它从未被引擎执行过。

| 边界 | 规则 |
| --- | --- |
| 入口 | 顶栏右上角「演练场 ↗」，次级入口 |
| 身份提示 | 进入后常驻一条：「演练场 · 模拟，不会改动你的项目」 |
| 内容 | 画布编辑、七类节点面板、配方广场八个预设、模拟剧本、案例回放、导入导出分享、图校验，功能零损失 |
| 可用性 | 离线和 demo 模式可用，无需先选目录、初始化 Git 或配置凭据。`#recipe=` 分享链接和案例文件直接进 Lab |
| 数据 | 只装模拟数据。真实运行的回放在 Build 底坞的时间轴里 |
| 订阅隔离 | 打开 Lab、点预设、选节点，都不得改写 Build 的实时订阅或选中的运行 |
| 画布实例 | 实时画布和 Lab 画布拆成两个宿主，删除 `liveViewActive` 标志及其约十处调用 |
| 唯一的桥 | 「带这套阵容去发车」，只携带 `_start_run` 真正消费的字段，不携带画布拓扑 |

有一处现状与「不会改动你的项目」冲突，迁移时必须处理：节点编辑会把角色默认值写入 `baton.toml`（`inspector/GraphEditor.tsx:203`）。该写入要么从 Lab 移除，要么改为显式的「保存为项目默认」并归入设置中心。

## 6. 全页术语透视镜（Term Lens）

现有 `GlossaryTerm` 与 `findFirstOccurrences` 不能原样推到全页。方案是两档开关、两条绑定轨道、一个单例浮层。

### 6.1 现有实现推全页会踩的七个坑

| # | 坑 | 源码依据 | 后果 |
| --- | --- | --- | --- |
| 1 | 中文界面几乎零命中 | 词条 `term` 是英文显示名，全库只有 3 处 `aliases` | 「预算档位」「配方广场」「门禁」都标不出来 |
| 2 | 补中文别名后无词边界 | `data/glossary.ts:88-90` | 「角色」「模型」这类短词到处误报；英文侧 Gate、Preset 等不区分大小写，同样成片命中 |
| 3 | 去重规则在界面上失效 | 「每段只标首次」为长文设计，`glossary.ts:110-135` | 界面上每个标签自成一段，每处都算首次 |
| 4 | 按钮套按钮 | 触发器是 `<button>`，`GlossaryTerm.tsx:105` | 非法嵌套，并劫持原点击 |
| 5 | 气泡被裁剪 | `position: absolute; left: 0`，无碰撞检测，`GlossaryTerm.css:31-52`；组件 CSS 有 38 处 `overflow` | 窄面板里向右溢出被切掉 |
| 6 | 画布内随缩放变形 | 节点在 React Flow 变换层内，最小缩放 0.2，`CanvasWorkspace.tsx:180` | 气泡缩到不可读，悬停还与拖拽、平移抢手势 |
| 7 | 悬停地雷阵 | 气泡一次塞五块内容，`GlossaryTerm.tsx:115-134`；多处已有原生 `title=` | 鼠标横穿侧栏扫出一串重气泡，并出现双提示 |

性能不是主要矛盾。真正的成本是每个术语一个带状态的组件，而运行面板每秒重渲染一次。

### 6.2 开关与退场

| 状态 | 页面表现 | 速查 |
| --- | --- | --- |
| 关 | 零装饰 | 顶栏「术语速查」仍可按中英文和别名搜索 |
| 开 | 只标用户还没点过「懂了」的词，每屏每词只标首次出现 | 同上 |

- 只有在浮层里点了「懂了」，该词才不再标记。不做隐式推断。
- 「重置已懂」放在术语镜菜单里。
- 一个切换快捷键替代按住 `Alt`，具体键位实现时避开浏览器保留键后确定。
- 每屏密度上限 8 个，超出时按「当前阶段相关词优先」截断。上限数值是设计建议，未经用户测试。
- 新用户的初始档位协商中没有定案。建议首次进入默认开，用户关过一次后记住选择。

### 6.3 绑定双轨与禁区

| 文本来源 | 机制 | 规则 |
| --- | --- | --- |
| 静态界面文案 | 显式 `<Term id="budget-profile">` | 不走正则，中文覆盖问题随之消失 |
| 动态 AI 文本（任务摘要、决策问题、验收摘要） | 受控匹配器 | 只在带 `data-term-scope` 的容器内运行；只匹配词库里标了 `autoMatch` 的无歧义词；拉丁词用 `\b` 词边界；中文只走审核过的长词组和别名，歧义短词不自动匹配 |

禁区（不做自动匹配，也不放行内标记）：

- 按钮、链接、输入框和标签页的文字。需要解释的控件旁边放独立的释义入口。
- 日志、代码、路径、SHA、RFC 编辑器。
- 画布节点内部。节点类型和端口的解释放进情境抽屉。

### 6.4 标记与浮层

| 关注点 | 方案 |
| --- | --- |
| 标记元素 | `<span role="button" tabindex="0">` 加虚线下划线。不上色，不与状态色抢语义 |
| 浮层 | 全页单例，`position: fixed` 加视口坐标，靠边翻转 |
| 挂载点 | 最近的 `data-term-host`：默认 `body`，弹窗内挂到该弹窗 |
| 画布 | 浮层不挂在 React Flow 变换层内 |
| 事件 | 根节点一个委托监听器，术语本身不带状态 |
| 鼠标 | 悬停约 350 ms 只出一句 `oneLiner`；点击展开通俗与专业解释、相关词和「懂了」 |
| 触屏 | 轻点直接展开 |
| 键盘 | 聚焦显示一句释义，Enter 展开，Esc 关闭并把焦点还回原处 |
| 原生提示 | 被 `<Term>` 接管的元素移除 `title=` |

## 8. 创新设计精选

入选标准只有一条：忠实投影后端已有的机械事实。凡是要预测、或要 LLM 叙述才能成立的，砍掉或降级。

### 8.1 Top 4

| 排名 | 特性 | 用户得到什么 | 期次与最小交付 | 尚未核实的前提 |
| --- | --- | --- | --- | --- |
| 1 | 蓝图 → 证据矩阵 | 验收时逐条回答：约定了什么、哪次门禁验证了它、改动落在哪、还缺什么 | P0 条件 × 门禁结果；P1 改动文件反查 | 无（结构已核实，缺显式外键） |
| 2 | 可点击交接棒连线卡与接力泳道 | 点两棒之间的连线，看到谁交给谁、交了什么、过了哪道门禁、为什么卡住 | P0 连线卡；P1 泳道时间轴，做成底坞的一个标签 | 每次交接是否都有落盘的交接物；每次尝试的起止时间是否够细 |
| 3 | Git 版本谱系时间机器 `A → B → C` | 在谱系轨上选目标、预览保留和丢弃什么、单次确认，替代三个并排红按钮 | P1 | 契约能否由「目标修订 + 意图」唯一确定回滚类型；是否有按运行读取 RFC 快照的接口 |
| 4 | 统一决策收件箱与隔夜交班晨报 | 所有需要人的事项收在一处；回来先看「自你离开以来」 | P1 收件箱；P2 晨报 | 需按运行保存阅读游标并支持补取历史事件 |

### 8.2 各项要点

**证据矩阵**（三态单元格，绝不推断通过）：

| 单元格状态 | 含义 | 显示 |
| --- | --- | --- |
| 有门禁回执 | 能追到一次门禁运行的结果 | 按回执如实显示通过或失败，可点回命令与输出 |
| 仅有改动文件 | 有文件改动佐证，没有门禁回执 | 中性色，不计入通过 |
| 未关联 | 找不到对应证据 | 中性色，写明「未关联」 |

- 「未关联」本身就是最有价值的信息。
- 改过文件不能证明条件通过。模型建议的映射必须由人确认。
- 返工直接从矩阵发起：勾选未满足的条件，带回下一轮蓝图。

**交接棒连线卡与泳道**：

- 连线卡内容：上一棒与下一棒、交付物与改动文件、门禁命令与退出码、审校结论、接手状态与阻塞原因。
- 实时图有一部分边由里程碑布局推导。首版必须把「流程关系」和「有事件佐证的实际交接」画成不同样式。
- 会诊溯源并入节点抽屉：panel 节点的「技术详情」里展示争议点、各方依据和综合者的取舍。没有分歧时不生成形式化的辩论。
- 泳道时间轴（P1）：每个模型一条泳道，横轴是时间，复用连线卡的同一批真实事件。

**谱系时间机器**：三种回滚现在是三个并排的红色按钮，区别只靠 `title` 提示说明（`GuidedSignOffPanel.tsx:777-803`）。改为四步：看到父子修订；选中目标并比较差异；预览保留什么、丢弃什么、作用于哪个分支；单次确认。三种回滚仍是后端语义，界面只按契约投影。

**收件箱与晨报**：

- 收件箱（P1）替代散落的横幅，决策、终审、失败、长冷却都进一个列表。
- 收件箱只指路，不审批。决策继续在原门禁或验收入口提交。
- 晨报（P2）是收件箱的派生视图，由事件确定性生成，不让 LLM 写摘要。

### 8.3 二期演进
